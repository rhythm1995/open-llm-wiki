## 文件即真相

应用不拥有你的数据。每一篇笔记都是磁盘上的普通 Markdown。关掉应用、换编辑器、用 git 克隆，文件还在。

列表、图谱、反链、健康分数都是派生物。缓存坏了，重新扫一遍 vault 就能还原。没有第二份藏起来的数据库。

Vault 就是你选中的那个文件夹。没有登录，没有厂商云，没有「我的库」服务端。最近路径只是本机偏好。两台电脑要同一座库：用 git、U 盘或你已经在用的同步工具搬那个文件夹。应用自己不提供同步。

想离开，带走 `.md` 即可。

## 编译，不要每次检索

常见的「LLM + 文档」回路是提问时再搜：上传文件、取出片段、生成答案、把综合扔掉。下一问又从零开始。什么也没积累下来。

这个应用走另一条回路。**原始材料不动。Wiki 被编译，并保持更新。** 你提炼一篇 Source，Agent 去改摘要、实体、概念和链接。你提问，它读这些页面。你打开库健康，孤儿、薄主张、矛盾已经是结构，不是一次性检索技巧。

你仍可以亲手写任何一页。Agent 是簿记员，不是文件夹的主人。

| 层 | 在这里 |
| --- | --- |
| 原始材料 | `type: Source` — Agent 只读，不改原文 |
| Wiki | Summary / Entity / Concept，加上你自己留的笔记 |
| 契约 | 库里的 `AGENTS.md` 和 wiki-ingest skill |

| 事 | 在这里 |
| --- | --- |
| 消化 | 在 Source 上点 **提炼进 Wiki** |
| 提问 | **问 Agent**，有用的回答写成新页 |
| 体检 | **库健康** — 分数、锁定检查、下一步 |

原材料写成 `type: Source`。理解写成另一篇 `type: Summary`。源变了，不要改旧摘要——标 `Superseded`，再写一篇。版本留给 git。

一条好回答如果只留在聊天里，这次编译就浪费了。写回文件。

## Vault 就是记忆

对话历史不是长期记忆。这个产品也不是向量库。**文件夹才是记忆**——和人浏览的是同一座编好的 wiki。

接 Agent 有两条路。它们共享文件，不共享聊天。

| | 应用内 Agent | 外部 Agent（MCP） |
| --- | --- | --- |
| 在哪聊 | 右侧栏 | Cursor / Claude Code / 其它编辑器 |
| 怎么接 | 本机配方（ACP） | 设置 → Agent 记忆 → 一键接入 |
| 工具 | 会话加上 `@` 笔记 | 同一座库上的八个 MCP 工具 |
| 原始对话 | 应用 SQLite，不进 vault | 那个编辑器自己的历史 |
| 什么算记忆 | 只有你（或 `write_note`）写下的文件 | 同样 |

`hot.md` 是给下一轮的短缓存，不是日志，也不是 wiki 本身。省 token 顺序：缓存 → `index.md` → 再 `read_note` / `links`。

## 链接优先于文件夹

文件夹适合放附件和草稿，不适合当分类系统。分类一变，你就得搬家。

这个应用把关系放在 `[[wikilink]]` 和 frontmatter 里。图谱是这张网的视图。反链不必手填：在 A 里写 `[[B]]`，打开 B 时右侧就会出现 A。

`type:` 和 `status:` 是标签，不是牢笼。它们从不拒绝保存。只影响分组、图标、库健康认谁是主张、以及 Agent 按哪份契约写新页。你可以完全不写 `type:`。wiki-starter 里的 Source / Summary / Entity / Concept 是一套**建议的工作方法**，让 Agent 和库健康有共同语言。

一篇主张是 `Active` 还是 `Contested`，只看那篇笔记自己，不看它在哪个文件夹。

## 库健康，不是查询语言

查询引擎在 Rust 里，能力足够强。但一门给人用的 DSL 要你学它、写它、维护它——每一层都在花你的时间。所以没有 QueryPanel。

人看到的是：

1. 从图谱即时算的分数；
2. 十一条锁死的问题；
3. 一句「下一步」；
4. 临时问题交给 Agent，用自然语言问。

QQL 仍在：MCP 的 `run_qql`、桌面健康扫描、starter 里的 `health/*.md`。它是给程序和 Agent 的中间表示，不是给你打字的语言。

## 飞轮

若你用 wiki-starter：

```
ingest（吃进 Source）→ 产出 Summary / Entity / Concept
        ↑                         ↓
   下一篇源？  ←  库健康告诉你缺口
```

「最饿主张」和「探索前沿」回答的是：下一轮该补哪篇、该链到谁。不必先成为档案学家。

多数笔记软件卖的是编辑体验。多数「LLM + 文档」产品卖的是检索。这个应用把**编好的 wiki** 做成一等公民：看得见的关系、能量的缺口、任何 Agent 都能当记忆用的文件夹——没有专有库。
