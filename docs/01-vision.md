# 01 — 愿景

## 它是什么

OpenObsidian(工作名)是一个**桌面端、本地优先、纯文件**的知识管理应用。每个笔记是一个 Markdown 文件;没有数据库、没有云端、没有账号。你的知识永远在你磁盘上,可被任何工具读取。

它以 **Tolaria 公开的设计思想为蓝本**,clean-room 重写(只读公开文档汲取方法论,零代码复制),并刻意补齐 Obsidian 生态里最被需要、却长期缺失或要靠插件拼凑的两件事:**原生图谱可视化** 与 **实时聚合查询**。

## 为什么造

市面两个最强参照物,各有结构性缺口:

- **Obsidian** —— 功能成熟、生态庞大,但核心理念是"空白画布":能力靠插件拼,实时聚合(Dataview)是社区插件而非一等公民,图谱在但偏弱;且其同步是专有商业线,文件格式虽开放,引擎闭源。
- **Tolaria** —— 有主张(method + convention over config + git-first + AI-native + relations as first-class),设计哲学强烈,但**刻意不做实时聚合**(saved views 只能筛不能算),**图谱可视化缺位**,且其 type 系统在某些工作流里显得绑人。

OpenObsidian 的论点:**把 Tolaria 的"有主张的文件优先"骨架,与 Obsidian 的"图谱 + 实时聚合"能力,原生缝合成一个 MIT 项目**。不是复刻其中任何一个,而是站在两者的公开肩膀上补那条缝。

## 差异点(逐条)

| 维度 | Obsidian | Tolaria | **OpenObsidian** |
|---|---|---|---|
| 文件格式 | 纯 md + frontmatter | 纯 md + frontmatter | 纯 md + frontmatter(三者互通) |
| 图谱可视化 | 有,偏弱 | 无 | **一等公民**,WebGL,可过滤/聚类/实时 |
| 实时聚合 | 靠 Dataview 插件 | 无(只能筛不能算) | **一等公民**,内置查询引擎(Rust,快) |
| 类型系统 | 几乎无 | 强约定、有主张 | **软约定**:可选、可忽略、永不绑人 |
| 同步 | 专有 Sync(付费) | Git 一等公民 | **Git 一等公民** |
| AI 友好 | 插件层 | 架构原生 | 架构原生(纯文件 + 约定 + MCP) |
| 许可 | 闭源引擎 | AGPL-3.0 | **MIT** |

一句话:**Obsidian 能力 + Tolaria 哲学,MIT,图谱和聚合做成原生**。

## 设计原则(优先级从上到下,冲突时上面的赢)

1. **文件即真相(Filesystem as source of truth)** —— app 永不拥有数据;所有 UI 状态都是从磁盘可重建的派生物。任何缓存失效后,完整状态可由重新扫描 vault 还原。
2. **零锁定** —— 每天赢得信任,而非用格式绑架。想走,带上你的 md 文件走。
3. **Git 一等公民** —— 同步、历史、协作、审计都走 Git,无专有云。
4. **约定优于配置,但约定不是牢笼** —— 标准 frontmatter 字段开箱触发富行为(status chip 等);用户可覆盖、可全忽略。**类型是可选标签,不是 schema 约束。**
5. **关系是一等公民** —— 笔记之间的连接和笔记本身一样重要;图谱、反向链接、聚合都建立在同一张关系图上。
6. **AI 原生架构** —— 纯文件 + 约定让 agent 不需额外配置就能读写 vault。提供 MCP server。
7. **本地优先、性能是特性** —— 大库(万级笔记)下图谱/搜索仍要快。性能关键路径在 Rust。
8. **可测试优先(TDD)** —— 核心逻辑(解析、图谱、查询)是纯函数、全测试、先写测试。

## 不做什么(诚实声明)

- **不做专有同步。** Git。
- **不做 SaaS / 云端服务。** 桌面 app。AGPL 不适用(我们是 MIT),但产品形态就是本地。
- **v1 不做插件系统。** 先把内核和两大差异化(图谱/聚合)做扎实;插件 API 是后期阶段。
- **不复刻整个 Obsidian 插件生态。** 不可能,也不该是目标。
- **不抓取网络内容。** 与 cairn 的"deliberate source"哲学一致:你决定吃什么。

## 构建原则:参考 Tolaria 的实现,而非从零臆造

为降低复刻复杂度,**直接参考 Tolaria 的代码与 UI 实现作为蓝本**——看它的架构、数据流、模块划分、算法思路、UI 模式,据此搭我们自己的。

**红线(守住 MIT 的关键):重写为我们自己的表达,绝不逐字或近似逐字复制 Tolaria 的代码。** Tolaria 是 AGPL,逐字复制的那部分事实上仍是 AGPL——会让"MIT 许可"落空。架构分层、数据流、通用算法(如 frontmatter 解析)多为**不可版权的思想/方法**,参考风险最低;具体 UI 设计与独特实现需以自己的表达重写。每处明显参考记入 [07-provenance](./07-provenance.md) 的溯源表。

## 灵感与归属

设计以 Tolaria 的**代码/UI 实现 + 公开文档**(VISION 等)为蓝本参考,与 Obsidian 公开功能描述对照。重写为我们自己的表达,MIT 许可;**未逐字复制任何第三方源码**。详见 [07-provenance.md](./07-provenance.md)。
