# 01 — 愿景

## 它是什么

OpenObsidian 是一个**桌面端、本地优先、纯文件**的知识管理应用。每个笔记是一个 Markdown 文件;没有数据库、没有云端、没有账号。你的知识永远在你磁盘上,可被任何工具读取。

它是**原创、独立的实现**(MIT),刻意补齐 Obsidian 生态里最被需要、却长期缺失或要靠插件拼凑的两件事:**原生图谱可视化** 与 **实时聚合查询**。

## 为什么造

最强的参照物是 Obsidian——功能成熟、生态庞大,但核心理念是「空白画布」:能力靠插件拼,实时聚合(Dataview)是社区插件而非一等公民,图谱在但偏弱;且其同步是专有商业线,文件格式虽开放,引擎闭源。

OpenObsidian 的论点:**把 Obsidian 生态最被需要、却长期靠插件拼凑的能力——图谱可视化与实时聚合——做成 MIT 项目里的原生一等公民**,而不是插件。文件优先、零锁定、Git 同步、AI 原生。

## 差异点(对照 Obsidian)

| 维度 | Obsidian | **OpenObsidian** |
|---|---|---|
| 文件格式 | 纯 md + frontmatter | 纯 md + frontmatter(互通) |
| 图谱可视化 | 有,偏弱 | **一等公民**,Cytoscape.js + cose 力导向 + 多布局(type 层/时间轴);过滤/健康/落盘 |
| 实时聚合 | 靠 Dataview 插件 | **一等公民**,内置查询引擎(Rust,快) |
| 类型系统 | 几乎无 | **软约定**:可选、可忽略、永不绑人 |
| 同步 | 专有 Sync(付费) | **Git 一等公民** |
| AI 友好 | 插件层 | 架构原生(纯文件 + 约定 + MCP) |
| 许可 | 闭源引擎 | **MIT** |

一句话:**Obsidian 同源能力,MIT 开源,图谱和聚合做成原生**。

## 设计原则(优先级从上到下,冲突时上面的赢)

1. **文件即真相(Filesystem as source of truth)** —— app 永不拥有数据;所有 UI 状态都是从磁盘可重建的派生物。任何缓存失效后,完整状态可由重新扫描 vault 还原。
2. **零锁定** —— 每天赢得信任,而非用格式绑架。想走,带上你的 md 文件走。
3. **Git 一等公民** —— 同步、历史、协作、审计都走 Git,无专有云。
4. **约定优于配置,但约定不是牢笼** —— 标准 frontmatter 字段开箱触发富行为(status chip 等);用户可覆盖、可全忽略。**类型是可选标签,不是 schema 约束。**
5. **关系是一等公民** —— 笔记之间的连接和笔记本身一样重要;图谱、反向链接、聚合都建立在同一张关系图上。
6. **AI 原生架构** —— 纯文件 + 约定让 agent 不需额外配置就能读写 vault。提供 MCP server。
7. **本地优先、性能是特性** —— 大库(万级笔记)下图谱/搜索仍要快。性能关键路径在 Rust。
8. **可测试优先(TDD)** —— 核心逻辑(解析、图谱、查询)是纯函数、全测试、先写测试。

## 不做什么(诚实声明)

- **不做专有同步。** Git。
- **不做 SaaS / 云端服务。** 桌面 app。AGPL 不适用(我们是 MIT),但产品形态就是本地。
- **v1 不做插件系统。** 先把内核和两大差异化(图谱/聚合)做扎实;插件 API 是后期阶段。
- **不复刻整个 Obsidian 插件生态。** 不可能,也不该是目标。
- **不抓取网络内容。** 与 cairn 的"deliberate source"哲学一致:你决定吃什么。

## 构建原则:原创实现,严守 MIT

本项目是**原创、独立的实现**:架构、数据流、模块划分、算法、UI 一律自写。

**红线(守住 MIT 的关键):绝不把 GPL/AGPL 等 copyleft 源码(逐字或近似逐字)引入本仓库。** 逐字复制的那部分事实上仍受原许可约束——会让「MIT 许可」落空。架构分层、数据流、通用算法(如 frontmatter 解析)多为不可版权的思想/方法;具体源码与视觉表达一律以自己的方式实现。

## 灵感与归属

面向 Obsidian 的公开功能描述做对照,补齐图谱可视化与实时聚合这两件最被需要、却长期靠插件拼凑的能力。所有源码、组件实现、视觉表达均为原创,MIT 许可;**未逐字复制任何第三方源码**。详见仓库根 [README](../README.md) 的「贡献」与「许可」。
