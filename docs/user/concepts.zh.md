## 文件即真相

应用不拥有你的数据。每一篇笔记都是磁盘上的一个普通文件。关掉应用、换编辑器、用 git 克隆，文件还在，内容还在。

界面上看到的列表、图谱、反链、健康分数，都是从这些文件算出来的派生物。缓存坏了，重新扫一遍 vault 就能还原。没有第二份藏起来的数据库。

所以：

- 用访达改文件名或移动文件，和下一次打开应用看到的是同一件事。
- 想备份，复制文件夹或 `git commit`。
- 想离开，带走 `.md` 即可。

## Vault 不是账号

Vault 就是你选中的那个文件夹。没有登录，没有云同步，没有「我的库」服务端。桌面端可以记住最近打开过哪些路径，那只是本机偏好。

两台电脑要同一座库：用 git、U 盘或你已经在用的同步工具搬那个文件夹。应用自己不提供同步。

## 洞察晶格，而不是文件夹树

文件夹适合放附件和草稿，不适合当分类系统。分类一变，你就得搬家。

这座应用把关系放在正文的 `[[wikilink]]` 和 frontmatter 的关系字段里。图谱是这张网的视图：节点是笔记，边是链接。主标上的灯泡就是这个隐喻——链接织成可被照亮的结构。

反链不必手填。你在 A 里写 `[[B]]`，打开 B 时右侧就会出现 A。

## 类型是标签，不是牢笼

`type: Concept` 不会启用一套必填表单，也不会在缺字段时拒绝保存。类型只影响：导航分组、图标颜色、健康查询认谁是主张、Agent 按哪份契约写新页。

你可以完全不写 `type:`，库仍然能用。wiki-starter 里的 Source / Summary / Entity / Concept 是一套**建议的工作方法**，让 Agent 和健康看板有共同语言。

`status:` 同样是约定。一篇主张是 `Active` 还是 `Contested`，只看它自己的 frontmatter，不看它在哪个文件夹。

## 来源不可变，摘要可废

把原始材料写成 `type: Source`，把你的理解写成另一篇 `type: Summary`。源变了，不要改旧摘要——标 `Superseded`，再写一篇新的。版本真相留给 git。

这就是「提炼进 Wiki」在做的事：吃进一篇 Source，产出派生页，而不是在原件上涂改。

## 库健康为什么不是查询编辑器

查询引擎在 Rust 里，能力足够强。但教人一门带字段名和渲染动词的 DSL，门槛叠了四层。所以用户面没有 QueryPanel。

人看到的是：

1. 从图谱即时算的分数（消化、达标、争议、孤儿、单源……）；
2. 十一条锁死的问题（孤儿有哪些、哪些主张证据不够）；
3. 一句「下一步」；
4. 临时问题交给 Agent 用自然语言问。

QQL 仍在：MCP 的 `run_qql`、桌面健康扫描、starter 里的 `health/*.md`。它是给程序和 Agent 的中间表示，不是给你打字的语言。

## 两条 Agent 路径

它们解决不同的问题，不要混成一条。

| | 应用内 Agent | 外部 Agent（MCP） |
| --- | --- | --- |
| 在哪聊 | 右侧栏 | Cursor / Claude Code / 其它编辑器 |
| 怎么接 | 本机安装的配方（ACP） | `open-llm-wiki-mcp` 注册进那个编辑器 |
| 原始对话 | 留在应用的 SQLite，不进 vault | 留在那个编辑器自己的历史里 |
| 进 vault 的东西 | 只有你（或 Agent 经 `write_note`）明确写下的文件 | 同样只有写进文件的内容 |

`hot.md` 是给下一轮对话的短缓存，不是聊天记录。应用内 Agent 会读它；写过库再提醒你覆写。外部 Agent 也应该先读它。

## 飞轮

若你用 wiki-starter 的方法：

```
ingest（吃进 Source）→ 产出 Summary / Entity / Concept
        ↑                         ↓
   下一篇源？  ←  research / 库健康告诉你缺口
```

健康看板的「最饿主张」和「探索前沿」就是在回答：下一轮该补哪篇、该链到谁。不必先成为档案学家。

## 和「又一个笔记软件」的差别

多数笔记软件卖的是编辑体验。这座应用把**关系**和**可度量的缺口**做成一等公民，并且让 Agent 能按同一张图读写，而不把文件锁进专有格式。

图谱不是装饰。库健康不是仪表盘玩具。它们是同一张关系图的两个面：一个给你看结构，一个告诉你结构哪里薄。
